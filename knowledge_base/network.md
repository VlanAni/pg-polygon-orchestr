## Подключение к сети

Когда контейнер без флага `--network`, он подключается к дефолтной сети (`bridge`/`default bridge`)

## Пользовательские сети

Пользователь может объявлять свои сети, и внутри пользовательских сетей контейнеры могут обращаться друг к другу как по `IP`, так и по **имени**

## Флаг `--internal`

Флаг `--internal` при создании сети позволяет сделать внутреннюю сеть, где контейнеры могут общаться только друг с другом, но ко внешним ресурсам обращаться не могут

## Сетевые настройки контейнера

Можно указать какой протокол использовать (`ipv4` или `ipv6`)

Можно задать имя контейнера в сети с помощью флага `--hostname` (по умолчанию там ID контейнера)

## Подсети

Сети в Docker можно разбивать на подсети при создании сети с помощью флага `--subnet` или настроить пул подсетей в `/etc/docker/daemon.json` как параметр `default-address-pools`, где `base` - сеть которую разбиваем, а `size`: длина префикса подести

## DNS

Если контейнеры подключаются к дефолтной сети, то они используют DNS-сервер который использует хост

Однако в кастомных сетях используется встроенный DNS-сервер (`127.0.0.11`), который перенаправляет запросы на сервер хоста

Можно указать для контейнера используемый dns по IP с помощью флага `--dns` 

## Сети контейнеров

Контейнер можно подключить к другому контейнеру напрямую с помощью `--network container:<name|id>`
